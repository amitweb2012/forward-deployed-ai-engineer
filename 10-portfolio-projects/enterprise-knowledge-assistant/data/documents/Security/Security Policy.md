# Security Policy — Sample

## Access management
Use individual accounts and grant least-privilege access. Access to sensitive systems and datasets must be approved by the resource owner and reviewed when roles change.

## Secure development
Never commit credentials or tokens. Validate input, keep dependencies updated, protect logs from sensitive data, and require review for changes that affect authentication or authorization.

## Data handling
Only store approved information in company systems. Avoid copying sensitive records into prompts, issue descriptions, and local demo environments.

## Reporting
Report suspected unauthorized access or exposed secrets promptly using the incident response process. Preserve evidence and follow instructions from the incident lead.

## Note
This is fictional sample content for the portfolio demo and must not be treated as official company policy.
